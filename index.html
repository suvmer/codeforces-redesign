Iterating over submasks: why the total is O(3n)

By dfs_tree, 5 hours ago · bitmasks tutorial

A short note, because I keep seeing this in my students' code. To process all pairs (mask, submask), people loop over all 2n values twice and check (s & mask) == s. That is 4n iterations. The standard idiom:

for (int mask = 0; mask < (1 << n); mask++) {
    for (int s = mask; s > 0; s = (s - 1) & mask) {
        // s is a non-empty submask of mask
    }
}

Every bit is in one of three states: not in mask, in mask but not in s, or in both. So the inner loop runs 3n times in total: for n = 18 that is about 3.9·108 instead of 6.9·1010.
